Problem

Agentic Unit Testing

“Test the maximum allowed retries.”

What the developer has to establish

  • Find the validator and read the retries() contract.
  • It accepts integers from 0 through 5 and rejects booleans.
  • Choose the upper boundary, assert its expected value, then run pytest and investigate failures.

Input to the agent

A Python repository path, a plain-language test goal, and model configuration.

Example test file

tests/test_agent_retries.py

from validation import retries

def test_maximum_allowed_retries():
    assert retries(5) == 5

What the developer gets back

Proposed test files, the outcome, tool trace, unresolved issues, and pytest and coverage results when available.

Design

Test generation workflows

Design

Memory System

  • Agentic RAG. The agent searches the repository on demand, ranks excerpts with TF-IDF, and checks exact source lines as needed.
  • Run context. Keep the four newest tool responses in full by default. Preserve the full trace for inspection.
  • Streamlit session. Keeps the latest verified test files and searchable history. Ask uses that history to answer follow-up questions. Revise tests updates the files in a fresh temporary copy and verifies them again.

Security Constraints

  • Screen instruction overrides and suspicious repository content. Exclude common credential files and redact sensitive patterns.
  • Limit writes to tests/test_agent_*.py. Bound tool use, time, and repair attempts.
  • Check generated Python before execution and run pytest with a reduced environment.
  • Mark the latest test files ready only with repository evidence, passing pytest, and fresh coverage.

The saved benchmark predates repository search and used the earlier full tool transcript.

Evaluation

Benchmark tasks and grading

50 tasks testing a Python batch-import codebase. 350 saved attempts across one baseline run and three runs per agent.

The codebase validates inputs, parses records, and looks up counts through a client.

1. Automated checks

Recreate the generated test files in a fresh copy of the Python codebase. Require pytest to pass with coverage and collect at least one generated test. For missing requirements, require unanswerable, no generated test files, and an explanation.

2. Separate model judge

Review correctness, grounding in evidence from the Python codebase, completeness, policy, and the task-specific rubric. Every applicable check must pass.
